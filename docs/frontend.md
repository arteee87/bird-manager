# Фронтенд

Панель управления — три файла, без сборки и без фреймворка:

| Файл | Роль |
|---|---|
| `templates/dashboard.html` | каркас: шапка, вкладки, панели, контейнеры редактора |
| `static/js/app.js` | вся логика — API-клиент, рендер, редактор, вкладки |
| `static/css/app.css` | оформление, включая раскладку с высотами и границы |

`app.js` подключается обычным `<script src>` без `type="module"`, `app.css` — обычной
ссылкой. Скрипт полагается на выполнение при загрузке страницы и работает в
состоянии `'use strict'`.

Страница отдаётся сервером с одним встроенным скриптом (версия в шапке), поэтому её
можно отдать под строгим Content-Security-Policy без `unsafe-inline` в разметке.

## Каркас страницы

```text
header            версия, банкер связи, кнопка ⟳
 └ section.tabs   единственная рамка приложения (#cbd5e1)
    ├ .tab-strip  три кнопки вкладок: Сети / BIRD / Система
    └ .tab-panels
       ├ Сети      две панели в ряд (сети | пиры) + формы добавления
       ├ BIRD      редактор конфигурации, сводка файлов, Apply
       └ Система   живые сессии BIRD, статус, бекапы, журнал
```

Все панели — `<section class="panel">` с заголовком и счётчиком.

По умолчанию свёрнуты: «Добавить сети», «Добавить BGP Peer» на вкладке «Сети», а также
«Статус конфигурации», «Бекап» и «Журнал» на «Система». Раскрыта только «BIRD peers» —
там живое состояние, за которым оператор следит. Свёрнутость задаётся тремя частями сразу:
у секции нет класса `expanded`, у кнопки стоит `aria-expanded="false"`, а у тела есть
класс `hidden`. Последнее обязательно: обработчик определяет состояние по `hidden` на
теле, поэтому секция без класса `expanded`, но с видимым телом схлопнулась бы по первому
клику вместо раскрытия. Состояние нигде не сохраняется — после перезагрузки панели
снова в исходном виде. Вкладки — кнопки с
`role="tab"`, панели — `role="tabpanel"`; активная вкладка несёт `aria-selected`,
неактивные панели скрыты атрибутом `hidden`.

Три ключевых константы раскладки заданы в CSS, а не в разметке: страница никогда не
скроллится целиком, `.tabs` занимает всю высоту вьюпорта между шапкой и полями, открытая
панель забирает свободную высоту, а длинный контент скроллится только внутри панели,
которой он принадлежит. Диапазон строк в больших списках ограничен переменными
высоты строки и рамки (`LINE_H`, `PANE_PAD`).

На вкладке `Система` это касается панели `BIRD peers`: раскрытая, она забирает всю
свободную высоту колонки и сдвигает панели под собой вниз. Открытая рядом панель тоже
растёт и забирает свою долю, поэтому нижняя граница `BIRD peers` уезжает вверх, а обе
скроллятся внутри себя. Контракт тот же, что у двух списков на `Сети`, просто сессии
лежат в одной колонке и должны при этом снять потолок `40vh`, общий с `Бекап` и
`Журнал`, — правило `.panel-bird-peers.expanded` его поднимает.

## API-клиент

```js
await apiFetch('/api/bgp_peers');
```

`apiFetch` — единственная точка общения с сервером:

- добавляет `API_BASE` (`window.location.origin`);
- разбирает ответ как JSON, при не-JSON подставляет пустой объект;
- при `res.ok === false` бросает `Error` с `message`/`error` ответа и
  `err.status` — кодом HTTP;
- при успехе снимает банкер «нет связи».

`safeFetch` оборачивает `apiFetch`: при ошибке ставит банкер связи, показывает тост и
возвращает `null` вместо исключения — вызывающий код не обязан быть в `try/catch`.
Фоновые опросы используют его, чтобы остановка демона не засоряла экран тостами.

`showToast(kind, text, timeoutMs)` держит не более пяти карточек одновременно, самые
старые вытесняются; ошибки живут 9 секунд, остальные 4. `endpointLabel` переводит
известные пути в читаемые имена, чтобы тост не показывал сырой URL.

Сообщения API — русские, и код отдаёт их в тост без перевода.

## Модель данных на вкладке «Сети»

Иерархия собирается в браузере из двух ответов — `/api/networks` и
`/api/communities`, — и группируется по `AS:COMMUNITY`; панель пиров приходит из
`/api/bgp_peers`. Обе панели стартуют свёрнутыми
и показывают только счётчик (`/api/networks/count`, `/api/bgp_peers/count`) — список
грузится лениво при первом раскрытии, чтобы не тянуть его на каждый клиент мониторинга.

### Поиск в «Сети и сообщества»

В заголовке панели есть поле поиска с подсказкой (ключ `m170`):
«Ввод текста — поиск по открытым строкам; Enter — поиск по всей базе».

- **Ввод текста (debounce 150 мс)** — поиск только по уже открытым (раскрытым)
  строкам; совпавшие строки подсвечиваются жёлтым (`search-hit`), текущая —
  более ярко (`search-current`). Счётчик `i/N` в правой части заголовка.
- **Enter** — поиск по всем записям. Разворачиваются только группы, где есть
  совпадение (по данным `HIERARCHY`, без рендера всех 54k строк). Совпавшие
  строки подсвечиваются и прокручиваются к первой.
- **◀ / ▶** — навигация по совпадениям без зацикливания; на границах кнопки
  disabled. **Esc** — сброс поиска и снятие подсветки.
- При отсутствии совпадений показывается «Ничего не найдено» (ключ `m169`).
- Placeholder поля: «Поиск…» (ключ `m171`).

### Массовое добавление

Ввод разбивается на части и отправляется несколькими запросами: тело запроса
ограничено `BIRD_MAX_BODY_BYTES`, и geo-фид перестаёт бы уместиться в один.

На всё время импорта открыт **один** модальный диалог `#bulk-progress`: разбор
частями, диалог проверки битых CIDR поверх него, поиск сообщества и запись
частями. Он открывается один раз и закрывается в `finally`, поэтому панель под
ним не оживает ни на секунду и не остаётся заблокированной, если что-то
выбросило исключение. Подпись фазы обновляется на каждом этапе, в том числе
между чанками: `Разбор: чанк 2 из 5`, `Проверка найденных CIDR`, `Подготовка`,
`Запись: чанк 1 из 3`.

Пока открыт диалог проверки, кнопка «Прервать» под верхним окном недоступна;
прерывание работает на фазах разбора и записи и проверяется перед каждым
запросом, а не посреди него. `Esc` в окне проверки означает «удалить битые,
продолжить». Уже записанные части остаются, повтор безопасен — сервер
пропускает префиксы, которые уже есть.

### Панель пиров

Список колонок — `DB_PEER_COLUMNS` (`app.js:277`). Под именем каждого пира рисуется
`scopeTag` — метка объёма выдачи:

| Условие | Метка |
|---|---|
| `export_all` включён | `все сети` |
| ASN пира найден среди сообществ | `N префиксов` |
| ASN не найден | `ASN не найдена` |

Значения `export_all`, `export_count` и `asn_found` приходят из API, поэтому надпись
в списке совпадает с содержимым `export.conf`. `N префиксов` и `все сети` описаны в
подсказке (tooltip) вместе с ASN.

Форма добавления (`renderBgpPeerPanel`) — только создание: идентификатор, локальный AS,
`neighbor` (строгий IPv4 без маски), `neighbor_as` и галочка `Отдавать все ASN` с
подсказкой «По умолчанию экспортируется только указанный Local AS.». Галочка снята по
умолчанию и стоит в одной строке со своей подписью, подсказка переносится под них
(`flex-wrap` в `.bgp-scope-field`). Элементу галочки намеренно **не** назначен общий
класс `field`: правило `.field input` растягивает контрол на всю ширину и отрывает
галочку от подписи.

Если ASN, указанный как Local AS, не встречается среди community, фильтр пира пуст и
отдаёт ноль префиксов — это ожидаемое поведение, а не ошибка формы; оно видно по
предупреждению после создания и по метке `ASN не найдена` в списке.

После успешного `POST` форма пишет в сообщение, сколько префиксов уйдёт пиру, а если
ASN не найден — предупреждение вместо обычного подтверждения.

Адреса и `neighbor_as` уникальны среди пиров; сервер отвечает `400` с текстом «уже
используется другим пиром (peer id / конфиг)», и этот текст показывается как есть.

### Конфиг RouterOS

В колонке `ROS` на строке пира лежит кнопка, которая по нажатию собирает конфиг для
RouterOS и показывает его в модальном окне: заголовок «Конфиг для <имя>», предупреждение
о ручной проверке input filter и ip address, сам текст и кнопки «Копировать» /
«Закрыть».

Текст строится функцией `rosConfigFor(peer, routerId)` из текущей записи пира и
`router_id` из ответа списка. Ничего не сохраняется: каждое нажатие пересобирает
строку заново, поэтому конфиг всегда соответствует тому, что сейчас в базе.

Подстановки: `birdmanager_<имя>` во всех трёх секциях, `as=<neighbor_as>` в instance,
template и connection, `local.address=<neighbor>`, `remote.address=<router_id>/32`,
`.as=<local_as>`, `.port=179`. Команды идут по одной в строке, без переносов, — результат
вставляется в терминал как есть. Значения `bgp-networks` и filter-chain `discard`
должны существовать на MikroTik заранее: конфиг их использует, но не создаёт.

Копирование идёт через `navigator.clipboard`, который работает только в secure context;
при прямом доступе по `http://<ip>` его нет, поэтому есть запасной путь через
`document.execCommand('copy')`, а если и он не сработал — текст выделяется, чтобы
Ctrl+C работал вручную.

Колонка `ROS` зафиксирована в CSS (`flex: 0 0 48px`) по той же причине, что и `.peer-act`:
незафиксированный трек измеряется как 0 в пустой ячейке шапки и по содержимому в строке,
из-за чего все колонки после него съезжают.

## Вкладка «BIRD»: редактор и Apply

Это единственная вкладка, которая **пересчитывается при каждом входе**: она заново
читает `/api/config/overview` и перерисовывает открытые секции. Кнопка ⟳ в шапке делает
то же самое, и оба пути идут через `refreshBirdTab`, чтобы их поведение не разошлось.

Две детали делают пересчёт честным, а не косметическим:

- модели строк кэшируются по имени файла и паре счётчиков, но пара `+1 −1` не способна
  заметить, что одна строка заменена другой. Поэтому пересчёт **сбрасывает кэш** и
  всегда доходит до сервера; из кэша берётся только обычное повторное открытие;
- выравнивание строк считает сервер (`old`/`new`/`kind` на строку) и никогда не
  пересчитывается в браузере, поэтому колонки не могут разойтись построчно.

`ROW_VIEW_MAX_ROWS = 5000` — за этой границей вид останавливается и показывается
пометка о под truncation; сам файл при этом продолжает редактироваться в
`<textarea id="active-config">`.

`networks.conf` — единственный редактируемый файл. `core.conf` и `bird-manager.conf`
показываются только для чтения, сводные файлы (`routes.conf`, `export.conf`) — в виде
строк с именем, путём и счётчиками.

Ошибка `bird -p` из другого файла бандла приходит текстом с именем файла и **не**
подсвечивает строку в редакторе: такой строки в редактируемом файле нет. Подсветка
рисуется только для ошибок, привязанных к `networks.conf`.

Apply отправляет текущий `networks.conf`, сервер валидирует весь бандл и только потом
публикует; ответ с `reload_warning` показывается отдельной строкой.

## Вкладка «Система»

Первой идёт read-only панель живых сессий из `birdc show protocols all` —
`loadBirdPeers` / `renderBirdPeers`. Она разделена на два блока:
`panel-bgp-sessions` (BGP-сессии, раскрыт по умолчанию) и `panel-service-protocols`
(сервисные протоколы, свёрнут). Блок BGP-сессий раскрыт по умолчанию, в отличие
от соседних панелей: это то самое живое состояние, за которым оператор следит, и
он забирает свободную высоту вкладки. Колонки — `PEER_COLUMNS` (`app.js:1259`):
`Managed`, `Peer`, `Neighbor`, `Neighbor AS`, `Local AS`, `Состояние`, `Префиксы`,
`Since`, `Last error`.

- Протоколы классифицируются по колонке `Proto`, поэтому в таблице есть и сессии,
  добавленные в `bird.conf` руками — они показываются с `Managed: no`.
- Пир, настроенный в панели, но отсутствующий в выводе BIRD, показывается как
  `нет в BIRD`, чтобы расхождение оставалось заметным.
- `Префиксы` — `rx`/`tx`; тире означает, что BIRD не напечатал строку `Routes`
  (обычное состояние сессии, которая не поднята), а не ноль префиксов.
- Ячейка `Состояние` содержит до двух бейджей: состояние канала (`UP`/`DOWN`) и
  состояние BGP (`Established`/`Active`/`idle`). Второй рисуется, только если он
  отличается от первого, чтобы не дублировать. Цвета семантические: зелёный — только
  `Established`/`up`.
- Время `Since` берётся из блока `BGP state:` и разбирается с учётом того, что BIRD
  печатает только `ЧЧ:ММ:СС.ммм` в день рестарта — такие значения относятся к текущим
  суткам, а не к 1970 году.

Опрос живёт в объекте `PeersPoll` (`app.js:1480`): таймер на `PEERS_POLL_MS = 30000`
запускается при активации вкладки и по кнопке ⟳, а любой ручной загрузчик сбрасывает
его. Условие «опрос идёт» проверяет `peersPanelVisible()` (`app.js:1264`): вкладка
`system`, панель в состоянии `expanded` и `document.hidden === false`. События
`visibilitychange` не подписаны — проверка происходит в момент тика, поэтому сворачивание
окна останавливает запросы, но таймер формально продолжает тикать вхолостую.

## Вкладки и роутинг

```text
#/networks  #/bird  #/system
```

`TAB_NAMES = ['networks', 'bird', 'system']` — список вкладок в коде; разметка и роутинг
согласуются с ним тестами. `handleRoute` разбирает хэш, `activateTab` переключает панели,
`ensureTabLoaded` подтягивает данные один раз за сессию вкладки. На кнопках вкладок
работает клавиатурная навигация roving focus: `ArrowLeft`/`ArrowRight` переключают
вкладку и переводят фокус, `Home`/`End` — к первой и последней.

`handleRoute` подписан и на `hashchange`, и на `popstate`, а фрагментная навигация
порождает оба события: измерение на этой машине дало три `hashchange` и три `popstate` на
три смены хэша, то есть ни одно событие не дублируется само, а вкладка включалась дважды.
Свои страховки у вкладок это скрывали: `Сети` гасила второй вызов в `ensureTabLoaded`,
`BIRD` — общим промисом в `refreshBirdTab`, и заметно стало только на `Система`, которая
перечитывает данные при каждом входе и потому брала всё по два раза. Поэтому `handleRoute`
сверяет `pathname + search + hash` с последним обработанным и выходит на повторе. Ключ
именно такой, а не только хэш, чтобы страховка пережила появление пути в маршрутизации.
Оба слушателя оставлены: убрать `popstate` было бы проще, но тогда переходы по истории
молча отвалились бы в день, когда роутинг получит путь. Клики по кнопкам и стрелкам
страховку не проходят — они зовут `activateTab` напрямую, поэтому повторный клик по
открытой вкладке по-прежнему её обновляет.

`Сети` грузится при первом открытии. `BIRD` и `Система` пересчитываются при каждом
входе. Для `Система` это не косметика: при уходе с вкладки останавливается `PeersPoll`,
а перезапускает его только конец `loadBirdPeers()`, который вызывается именно при загрузке
вкладки. Через однократный `ensureTabLoaded` таймер оставался бы остановленным, а таблица
сессий и панели статуса, бекапа и журнала показывали бы данные первого визита. При перезагрузке страницы раскрытые секции конфигурации восстанавливаются из
`collectExpandedConfigSections`, а открытые сводные файлы — из
`reopenSummaryViews`.

Счётчики на вкладках обновляются отдельным `refreshCounts`, который дёргает
`refreshDashboard`; на панели есть кнопка ручного обновления.

## Хранилище состояния

Состояния в `localStorage` нет. Всё, что переживает перезагрузку, живёт в хэше и в
разметке; счётчики кэшируются в переменных модуля на время страницы.

## Как править

- Имена API-путей и русские подписи — в одном месте: `DB_PEER_COLUMNS`,
  `PEER_COLUMNS`, `SECTION_FILES`, `STATUS_BADGES`, `ERROR_LABELS`.
- Любая функция верхнего уровня должна быть вызвана откуда-то в `app/` или `tests/`.
  Тест `test_no_unreferenced_module_level_functions` в `tests/test_api.py` считает
  неиспользуемые функции модуля и падает на них, так что «заготовка на будущее» без
  вызова не останется незамеченной.
- Синтаксис проверяется без браузера: `node --check static/js/app.js`.
- Правки оформления не должны вводить вторую рамку вкладок: внешнюю рамку приложения
  даёт `.tabs`, `.tab-strip` и `.tab-panels` — только контейнеры без рамок.
